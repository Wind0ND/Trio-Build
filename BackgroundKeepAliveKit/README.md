# Background protection

Independent module for protection policy, audio lifecycle, bounded source-refresh leases, settings UI and Chinese strings. Existing off/smart/always preference keys are retained; periodic is an additional experimental option. Legacy stall/max-session preferences remain readable but no longer change the six-minute cutoff or impose an automatic playback cap.

Automatic mode stops the audio engine while accepted readings are current. At six minutes without a valid update, if iOS still gives execution time, it attempts silent audio until valid data resumes. There is no additional delay or playback-duration cap. Continuous mode attempts audio throughout the background session. Periodic mode defaults to a total30-minute cycle with5minutes on and25minutes off; both are configurable. Its phase uses monotonic uptime, and suspension can delay, shorten or skip windows. Session time is estimated enabled time this launch, not rendered audio duration or battery usage. Audio mixes with other apps and yields to alarms.

Core Bluetooth background callbacks and state restoration remain primary. `com.trio.cgm.sourceActivity` indicates an actual valid live wake, not a stored sample. It can retry protection after competing audio ends and trigger recovery when stored samples are overdue. It never advances sample freshness. A throttled host refresh has a finite system background-task lease, completion token and20s timeout; `completed` means the request ended, not that fresh data arrived. Only accepted measurement timestamps decide recovery.

Default diagnostic export uses the common allowlisted `keep_alive` feature (audio/reminder/data/source/lifecycle/recovery). Repeated identical successful events are limited to once per5min. It contains no glucose values, sensor IDs, raw errors or audio-app identities. System interruption reminders use neutral titles when host alert privacy is enabled; original sound behavior remains.

iOS controls execution, Bluetooth relaunch and audio privileges. Neither silent audio nor an in-process timer guarantees indefinite running or revival after a user force-quit. Video, calls, radio loss, memory pressure and actual sensor/decoder faults still need physical-device testing. Apple references: Core Bluetooth background processing guide; TN3115; AVAudioSession interruption handling. In iOS26, an instantiated CBManager plus an existing Live Activity can receive additional Bluetooth background privileges; this is not a general-purpose permanent-execution entitlement.

Host integration: configure source-present/opaque source-epoch checks, refresh callback, private reminder title and outage-journal adapter in TrioApp. BaseFetchGlucoseManager captures the source before fetching and synchronously reports valid CGM timestamps after successful storage, then schedules the main-actor update. A persisted source-owned snapshot lets the deadline check see the store before its UI callback runs. Changing source or explicitly replacing its manager starts a new epoch; manual, future, simulator and old-source data cannot seed a real source's watchdog. Legacy database dates have no source provenance, so the first current-source store establishes the upgraded snapshot.

A serialized latest-desired-state writer orders notification replacement/removal; healthy five-minute readings schedule six-minute deadlines. Newer but still stale backfill retains the existing due episode, including across relaunch. Delivered watchdogs are archived before clearing; merely scheduled requests are not archived as deliveries. The scheduled request is not proof of hearing a sound. Periodic diagnostics include completely missed windows without catch-up playback. The Extensions screen embeds KeepAliveSettingsSection. Ottai's missed-grid repair and the six-minute ActivityKit display expiry remain separate.
